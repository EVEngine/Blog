# EVEngine v0.5.0 正式发布：从游戏运行时走向可组合创作平台

EVEngine v0.5.0 已正式发布。

这是一次覆盖面很广的更新：它既增加了 Mesh Modifier、Spline、UV Paint、VRM 1.0、UE 骨骼资源、风格化水体、布料、绳索和软体等直接可见的能力，也继续收敛编辑器、物理、程序化生成与 AI 工具之间的底层边界。

如果要用一句话概括 v0.5.0：**EVEngine 正在从一套拥有大量独立功能的游戏运行时，走向一套可以由项目、工具和 Agent 自由组合的创作平台。**

## 下载 v0.5.0

本次 Release 提供五个平台的 SDK：

- Windows
- Linux
- macOS
- Android
- iOS

所有压缩包都附有 `SHA256SUMS`，可用于验证下载文件。完整附件与发布信息见 [EVEngine v0.5.0 Release](https://github.com/EVEngine/EVEngine/releases/tag/v0.5.0)。

发布流水线完成了 26 项严格检查，并通过 SDK 打包、产物挂载、消费端与跨平台验证。v0.5.0 不是只从开发分支切出的一个标签，而是经过完整发布门禁验证的正式版本。

## v0.5.0 的重点更新

### 1. 完整推进动态网格创作

v0.5.0 加入了新一代 Mesh Authoring 工作流：

- Mesh Modifier Graph，可组合 Bend、Twist、Noise、Spherify、FFD、Cut 等操作；
- Spline 路径编辑与沿路径生成；
- Mesh Boolean 与 Geometry Stroke；
- 顶点选择、轴向 Gizmo、运行时 Sculpt 和 Undo；
- UV 投影与动态纹理绘制；
- 物理碰撞驱动的网格变形。

这些能力围绕同一份动态网格协作，可以出现在桌面编辑器、游戏内建造模式或自动化工具中，而不依赖某个固定 UI。更多设计与示例见上一篇文章：[从样条到动态网格：EVEngine 的新一代 Mesh Authoring 工作流](mesh-authoring-workflow.html)。

### 2. 物理系统从“功能集合”走向运行时组合

新版本继续扩展物理能力，并重点解决多个系统一起运行时的所有权和生命周期问题：

- Cloth2D / Cloth3D 向更完整的布料约束与交互能力推进；
- 新增模块化 Rope3D 与体积 SoftBody3D；
- Scene 可以把生成式碰撞体绑定到项目拥有的 gameplay `World3D`；
- PixelWorld 可以把权威像素地形投影为 Box2D 碰撞边界；
- Vehicle 使用带 generation 的 `PhysicsLink`，不再跨帧保存危险的裸指针；
- 2D / 3D world snapshot 升级到 schema v2，恢复失败不会部分修改 live world；
- 多个 CPU / GPU provider 可以按稳定优先级选择，回退原因保留结构化诊断。

这套架构的重点不是“再增加一个 Solver”，而是让生成、场景、车辆、像素世界和存档恢复能安全地使用同一个物理运行时。详细介绍见：[让物理世界真正组合起来](physics-runtime-composition.html)。

### 3. 更实用的角色、动画与资产管线

v0.5.0 的角色内容管线有明显进展：

- VRM 1.0 导入，覆盖 MToon、视线与 Spring Bone；
- UE 骨骼资源、可扩展 skin palette 与 PBR 材质支持；
- 动态骨骼、Foot IK、重定向角色运动与动画示例；
- Blender 场景热重载；
- Unity package、静态 prefab、sprite animation 与 shader mesh effect 导入；
- 程序化顶点法线与 normal-map bake。

目标不是为每种来源建立一座孤岛，而是把外部资产转换为 EVEngine 自己的资源、动画与渲染对象，使其能够继续参与热重载、编辑和跨平台运行。

### 4. 画面与玩法表现继续扩展

这一版本还加入或完善了多组可直接用于项目的表现能力：

- 可配置风格化水体；
- HD2D 景深与精灵深度表现；
- 大地图战争迷雾 MapFog；
- Interior Mapping 室内映射示例；
- GPU Surface Ink 与持久 RGBA8 Canvas；
- Mesh VFX 工具包；
- 可伸缩地形 streaming 与编辑器持久化；
- 资源网格的有界异步加载。

仓库中的示例覆盖角色、地形、关卡设计、网格变形、风格化渲染与游戏内编辑，可以作为新项目的直接参考。

### 5. AI 推理与 Agent 开发闭环

v0.5.0 增加了基于 EVEngine Tensor / Vulkan 后端的量化 ONNX 推理流程，并推进了 Squirrel 与 Tensor GPU 后端上的演化学习能力。

开发工具侧加入 EveScript LSP、带名称的调试器调用栈、Play Host、Play Trace 与证据门禁。Agent 不只可以调用引擎 API，还能读取结构化错误、观察运行状态，并用真实运行结果判断一次编辑是否完成。

这与 EVEngine 的整体方向一致：AI 是引擎工具链的一等使用者，但它必须走与人类工具相同的受检接口，而不是绕过生命周期、结果和事务规则。

## 从 v0.1.0 到 v0.5.0：最重要的版本演进

v0.5.0 也是一个适合回头观察的节点。下面不是完整 changelog，而是每一代版本最重要的方向变化。

### v0.1.0：建立可以正式发布的引擎基础

2026 年 8 月发布的 v0.1.0 完成了第一个正式版本闭环。

它的重要意义包括：

- 确立 `main`、`dev`、版本分支与自动发布流程；
- 提供 Windows、Linux、macOS、Android、iOS 五平台 SDK；
- 推进 Vulkan 渲染、FrameGraph、视锥剔除、动态 UBO 与多缓冲 Mesh 更新；
- 建立模块清单、依赖分层、结构检查与跨平台测试门禁；
- 打通 Squirrel 游戏脚本、ECS、场景、资源热重载和基础 AI 工具链。

v0.1.0 回答的是最基础的问题：EVEngine 能不能作为一套可下载、可构建、可运行、可持续发布的引擎存在。

### v0.2.0 / v0.2.1：让 SDK 真正可被外部项目消费

v0.2 系列把重点放在 SDK 体验、跨平台打包和消费端验证上：

- `eve build`、`eve get android` 与跨平台 packaging 流程逐步完整；
- 打包后的游戏在目标平台上接受真实启动验证；
- headless Vulkan 让 GPU 功能测试不再依赖可见窗口；
- WebGPU playground、异步截图、3D offscreen canvas 与 GPU-driven 渲染继续发展；
- 加入 bindings 与文档的一致性检查；
- v0.2.1 集中修复 macOS MoltenVK、运行时库、Windows VC++ runtime 与跨平台 SDK 包装问题。

这一代解决的是“引擎仓库能运行”和“别人拿到 SDK 能运行”之间的差距。

### v0.3.0：从运行时 API 走向可组合创作工具

v0.3.0 的关键词是“可组合”：

- Host-neutral Editor API v2 与 runtime builder；
- 通用编辑目标、工具会话、约束、笔刷、事务、Overlay 与 Inspector；
- 响应式桌面编辑布局、语义图标与声明式 UI；
- Procgen 参数 schema、材质配方 schema 与可反射 UI；
- 动画 Pose Graph、Root Motion、Notify、IK、Motion Matching 与 GPU Skinning；
- Dialogue 的 Yarn / Twee 导入、本地化、语音和口型同步；
- 2D / 3D Cloth、Snow、Surface Fluid、Decal、Atmosphere、Vehicle 与 Crowd 等模块。

从这一版开始，EVEngine 不再假定所有项目必须使用同一个大编辑器。底层能力可以由项目自行组合成桌面工具、游戏内编辑器或专用流水线。

### v0.4.0：WebGPU 对齐与大型运行时系统成形

v0.4.0 的两条主线是渲染后端对齐与完整玩法系统：

- WebGPU 覆盖 deferred、PBR、阴影、AO、GI、反射、体积效果、天气、草地、风格化效果与 Virtual Geometry；
- GPU-driven 提交、compute culling、visibility buffer 与 HZB occlusion 进入 WebGPU 路径；
- 加入专业粒子播放、GPU-resident simulation、ribbon、soft particle、lit material 和 effect asset；
- 建立 UE 风格 PCG：分区、生成源、增量失效、预算、缓存、biome grammar 与跨后端 point compute；
- EveScript 进入引擎工具链；
- RPG、战斗 Ability、Tactics、NPC AI、PixelWorld、Card Game 等系统形成更完整的产品循环；
- 热重载、资源依赖图和 live editing session 获得事务化保证。

这一代证明 EVEngine 的模块化架构不只适合小 Demo，也能承载更大的渲染和玩法系统。

### v0.5.0：把创作、运行时与自动化真正连接起来

v0.5.0 延续前几版的方向，但更强调系统之间的连接：

- 动态网格从算法集合变成完整创作工作流；
- 物理模块开始共享明确的运行时组合、快照与后端契约；
- Unity、Blender、VRM 与 UE 资产进入原生资源管线；
- 项目可以组合自己的场景、动画、Avatar、Biome、UI Theme 与关卡设计工作区；
- Tensor 推理、EveScript 工具和 Agent 观察接口共同形成自动化闭环。

它不是演进的终点，但标志着 EVEngine 的关注点已经从“有没有这个功能”进一步转向“这个功能能否被项目安全组合、被工具稳定编辑、被 Agent 可靠验证”。

## 接下来

后续开发会继续沿三条主线推进：

1. 补全物理快照拓扑与更多 CPU / GPU Solver 的统一装配；
2. 扩展 Mesh Authoring、场景编辑和资产导入的实际项目工作流；
3. 让 Vulkan、WebGPU 和移动平台在更多功能上保持可验证的一致行为。
