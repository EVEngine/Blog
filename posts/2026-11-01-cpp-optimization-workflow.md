# 优化 C++ 引擎，先别急着加 std::move：从告警到收益的完整链路

“这个对象是不是多复制了一次？”是 C++ 引擎开发里常见的问题。一个项目有大量调用点时，靠人工逐页阅读很难覆盖，于是我们给 EVEngine 的调用审查加入了扫描脚本和 clang-tidy 分析。

但扫描出一千条建议，不等于发现一千个性能问题。有些复制承担快照语义，有些按值参数最终发生移动，还有些建议只有在理解对象生命周期后才能决定是否采用。

这篇讨论整体优化工作怎样组织，并用动画图构建中的一处局部优化说明验证方法。案例来自截至 2026 年 11 月 1 日的本地工作分支；本文不把这些改动和测量写成正式版本已经发布的收益。

## 先把“可疑调用”变成可追踪的队列

第一层扫描适合覆盖范围：查找容器遍历复制、字符串临时对象、可疑返回方式、重复构造等模式。它速度快，也会产生误报。

第二层用真实编译参数驱动语义分析。宏、模板和平台头文件会改变代码的含义；没有正确编译上下文，工具可能连参与调用的类型都判断不准。编译数据库没有覆盖的文件，也应明确列为覆盖缺口。

EVEngine 的本地审计工具有 `--compiled-only` 等选项，配合构建目录运行分析。这个选项的意义是限定可分析范围，不代表整个仓库都已得到语义审查。

之后为每条诊断记录位置、规则、处理状态和理由。已确认需要保留的复制同样应该入账，避免下一轮又把它当作新问题。文件内容变化时，还需要复查旧结论是否依然适用。

## 决策之前，先问对象归谁所有

例如：

```cpp
const GraphNodeId fromNode = pinOwners.at(edge.from);
```

如果 ID 内部拥有较长字符串，按值获取会创建一份独立对象。若这里只做同步查询，且 owner 在整个使用期间稳定存在，局部引用可以省去不必要的复制：

```cpp
const GraphNodeId& fromNode = pinOwners.at(edge.from);
```

在 EVEngine 的动画图构建案例中，`pinOwners` 是函数内创建的映射，边遍历期间不再修改；这两个 ID 只用于查询和写入其他映射，引用不会跨回调或逃逸出构建过程。因此可以使用局部引用，最终状态机仍保存自己需要的名称。

反过来，如果把引用捕获进异步任务、长期保存 `string_view`，或者修改容器导致被引用对象失效，同样的改写就可能制造悬空引用。优化必须画清楚所有权边界。

## 局部测量应该有明确口径

这个案例的本地分配探针使用 MSVC Debug CRT，构造 128 条边和较长节点 ID，对比按值与局部引用两种循环。记录结果是：分配次数从 1152 次降到 640 次，分配请求字节从 86016 降到 53248。

两种写法都还需要构建结果映射，因此优化后的分配次数不会归零。探针还比较两份结果是否相等，避免只测出“做得更少”，却没有检查产物。

这些数字只描述该输入与该构建配置下的局部循环。它们不能换算成整个引擎快了多少，也不等同于峰值内存下降。如果正常游戏很少重建动画图，帧率可能几乎不变；收益更可能体现在编辑器批量构建或大型图加载阶段。

相关回归还覆盖构建后清空输入图，再确认状态机仍能切换，检查引用优化没有意外改变结果的所有权。现有本地日志记录了 16 项相关测试通过；这不是完整跨平台回归的替代品。

## std::move、noexcept、final 不是通用加速按钮

`std::move` 表达允许移动的意图，最终是否移动取决于类型、重载和 const 等条件。返回局部变量时无条件添加它，还可能妨碍 NRVO。工具提示“可以移动”后，依然要确认后面是否继续使用源对象。

`noexcept` 是异常契约。它可能影响标准容器选择移动还是复制，但必须在函数确实满足承诺时使用。声明不抛异常而实际抛出，会终止进程；它不是消除异常成本的万能注解。

`final` 可以帮助编译器理解继承边界，但收益取决于调用点和优化器已有的信息。没有证明它是热点，就不应把批量加标记当作主要优化成果。

## 整体优化需要回到帧预算

调用点审计只是其中一层。引擎还应检查重复资源上传、临时缓冲区、跨语言边界调用、数据布局、绘制批次和 CPU/GPU 同步等待。

可以按实际场景组织预算：启动与资源加载、稳定游戏帧、编辑器操作、批处理工具分别测量。稳定帧还要观察慢帧分布，平均帧率无法解释偶发卡顿。

对于一条建议，至少形成“定位 → 理解所有权 → 修改 → 检查行为 → 测量成本”的闭环。对高频路径优先做测量，对低风险且理由明确的复制消除保留简洁证据；对风险大、收益不明的改动，允许结论是保留原写法。

真正可持续的优化工作，最终会留下能重复使用的工具、说明为什么不改的审查记录、能保护生命周期的回归，以及口径清楚的测量。这样的结果比一份不断增长的“已消除告警数量”更有参考价值。
